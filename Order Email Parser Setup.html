Order Email Parser Setup
Setup guide

Order Email Parser

A Chrome extension that reads order-confirmation emails from Gmail (read-only), turns each one into JSON with Gemini, and keeps a history per Gmail account. These steps take you from a fresh machine to orders appearing in the extension. Plan on about 30 minutes.

Gmail→Chrome extension→Local proxy :8787→Gemini→SQLite history

What you need before starting

Item Used for Where to get it
Node.js 24+ and pnpm 11+ Running the project nodejs.org, then corepack enable
Google Chrome 116+ The extension (Chrome only; Edge and Brave won't work) google.com/chrome
A Gmail account The inbox the extension reads Any personal Gmail
Google Cloud project Gmail sign-in (OAuth) console.cloud.google.com, created in step 3
Gemini API key secret Parsing emails into JSON aistudio.google.com/apikey
Gmail App Password secret Sending mock order emails for testing myaccount.google.com/apppasswords (needs 2-Step Verification)

The two secrets go only into local .env files, which are ignored by git. Never paste them into chat or commit them.

Steps

  1. Install the project

    Open a terminal in the project folder and run:

    pnpm install
cp apps/server/.env.example apps/server/.env
cp apps/extension/.env.example apps/extension/.env
cp packages/test-emails/.env.example packages/test-emails/.env

  2. Fix the extension's ID

    Google sign-in and the local proxy are both tied to one extension ID, so it has to stay the same. Generate it once: 

    pnpm gen:key --write

    Write down the Extension ID it prints (32 letters, a–p). Steps 3 and 4 need it. Keep the generated extension-key.pem private.

  3. Set up Google sign-in

    In Google Cloud Console, with your project selected:

    1. APIs & Services → Library → search "Gmail API" → Enable.
    2. Google Auth Platform → Branding: app name Order Email Parser, your support email.
    3. Audience: choose External, leave it in Testing, and under Test users add the Gmail address you'll use.
    4. Data Access → Add or remove scopes: add https://www.googleapis.com/auth/gmail.readonly.
    5. Clients → Create client: type Chrome Extension, Item ID = the Extension ID from step 2. Copy the Client ID.
    apps/extension/.env 
    OAUTH_CLIENT_ID=1234567890-xxxxxxxx.apps.googleusercontent.com

  4. Add the Gemini key

    Create a key at aistudio.google.com/apikey and fill in:

    apps/server/.env 
    GEMINI_API_KEY=your-gemini-key
ALLOWED_ORIGINS=chrome-extension://<your Extension ID>

    Optional check that the key works. It parses three built-in sample emails and prints PASS or FAIL for each: 

    pnpm eval:live

  5. Start the local proxy

    pnpm dev:server

    It should print Order parser proxy on http://127.0.0.1:8787. Leave this terminal open while you use the extension.

  6. Build and load the extension

    pnpm build
    1. Open chrome://extensions and switch on Developer mode (top right).
    2. Click Load unpacked and choose the folder apps/extension/dist.
    3. Check that the ID on the card matches your Extension ID.
    4. Pin the extension, click its icon, and choose Sign in with Google. Approve "Read your email messages and settings".

  7. Send yourself mock order emails

    Real orders need real payments, so the project sends realistic Mytheresa, Selfridges and Revolve confirmations to your inbox instead. Turn on 2-Step Verification, create an App Password, then fill in:

    packages/test-emails/.env 
    SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=sender@gmail.com
SMTP_PASS=your16charapppassword
    pnpm send:test-emails --to you@gmail.com

    Each email has a fresh order number and [TEST ORDER] at the end of its subject. Send them to the same Gmail address you signed in with.

  8. See it work

    In the extension tab you can do either of these:

    • Tick Auto-check new mail every minute before sending the test emails. Within about a minute of them arriving, they appear in History, marked auto.
    • Click Search Gmail at any time. Every matching email not already in History is parsed right away.

    Each History entry shows the products and, under JSON, the full record.

What each parsed item looks like

order.items[] (one per product) 
{
  "name": "Rosalind Mini Dress",
  "brand": "Lovers and Friends",
  "colour": "Black",
  "size": "S",
  "quantity": 1,
  "price": 228,
  "currency": "USD",
  "imageUrl": "https://placehold.co/420x560/111111/ffffff/png?text=Rosalind+Dress"
}

Each order also has the retailer, order number, date and total. price is what was actually paid (the sale price if discounted). Any field the email doesn't contain is null rather than a guess.

Good to know

Only order emails are read

An email is parsed only if it comes from mytheresa.com, selfridges.com or revolve.com, or has [TEST ORDER] in its subject. Everything else in Gmail is ignored.

Read-only Gmail access

The extension can't send, delete or change mail. Chrome keeps the sign-in; tokens are never saved by the extension.

No back-fill

Auto-check only picks up mail that arrives after it's switched on. Use Search Gmail for older emails.

Weekly sign-in

While the Google app is in Testing mode, Google asks you to sign in again about every 7 days.

If something goes wrong

"Access blocked: app has not completed verification"Add your Gmail address under Audience → Test users (step 3).
Sign-in fails with "bad client id"The OAuth client must be type Chrome Extension, and its Item ID must equal the ID shown on chrome://extensions.
"The proxy rejected this extension"ALLOWED_ORIGINS must be exactly chrome-extension://<Extension ID>. Restart the proxy after editing.
"Cannot reach the parsing proxy"Start it with pnpm dev:server and keep that terminal open.
"Gemini returned HTTP 400: API key not valid"Fix GEMINI_API_KEY in apps/server/.env and restart the proxy.
"N emails in the queue, not parsed yet"The proxy was down or Gemini was busy. They're tried again every minute, up to 5 times. After that, click Search Gmail.
Test emails never appearCheck Gmail's Spam folder and mark them "Not spam". The subject must end with [TEST ORDER].
send:test-emails says "could not log in"Use a Gmail App Password, not your normal password. 2-Step Verification must be on.
Full details, including the manual test plan and every testing method, are in README.md and TESTING.md in the project folder.
